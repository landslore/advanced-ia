Plan 02 · Aprender construyendo · 12 semanas

Conviértete en AI Builder.

Diseña, construye y publica proyectos útiles con agentes de IA, aunque hoy no sepas programar ni usar GitHub. Aprenderás a especificar lo que quieres, revisar cambios y automatizar la publicación.

4–6 h por semanaPrincipiante totalProyecto final publicadoGratis para empezar

El método

Tú eliges el problema, el alcance y los criterios de calidad. El agente propone y construye. Tú revisas specs, cambios, pruebas y publicación antes de aceptar.

Tu papel

Product owner y revisor

Defines para quién es, qué debe hacer y cómo comprobarlo.

El agente

Constructor asistido

Redacta planes, edita archivos y ayuda a depurar. Su trabajo se revisa.

Tu criterio

Calidad y seguridad

Pruebas la experiencia, cuidas los datos y sabes volver atrás.

Herramientas sugeridas: cuenta GitHub Free, GitHub Desktop para manejar Git visualmente, GitHub Pages y un agente de código que ya tengas (Codex, Copilot, Cursor u otro). No necesitas pagar varias suscripciones al inicio.

Progreso

Ruta de 12 semanas

Completa las actividades primero; al final de cada módulo encontrarás una autoevaluación desplegable.

Semana 1 · La web y los proyectos

Entender las piezas sin jerga

Proyecto, archivos, frontend/backend, navegador, URL, hosting y entorno local.

  • MDN: tu primer sitio web
  • GitHub: publicar una web con Pages (vídeo)
Taller: escribe una idea en una frase, dibuja 3 pantallas y explica quién las usaría.
Semana 2 · GitHub visual

Guardar historial y trabajar con cambios

Repositorios, commits, ramas, pull requests y cómo volver atrás. Sin línea de comandos.

  • GitHub Hello World (no requiere saber programar)
  • Primer repositorio con GitHub Desktop
  • GitHub Skills: Introduction to GitHub
Taller: crea un repo de práctica; cambia el README en una rama, abre un PR, revísalo y fusiónalo.
Semana 3 · Briefs para IA

Pasar de idea vaga a alcance claro

Usuario, problema, casos de uso, restricciones, fuera de alcance y preguntas abiertas.

  • OpenAI Academy: AI Foundations / Build with AI
  • DeepLearning.AI: prompting para desarrolladores
Taller: redacta el brief de una web pequeña. Pide al agente que enumere dudas y haga preguntas; aún no le dejes construir.
Semana 4 · Specs y aceptación

Describir comportamiento comprobable

Requisitos, escenarios Given/When/Then, accesibilidad, estados vacíos y definición de terminado.

  • Gherkin: escenarios de aceptación
  • GitHub Spec Kit: documentación SDD
Taller: transforma cinco frases vagas como “rápido y bonito” en criterios observables y comprobables.
Semana 5 · SDD y OpenSpec

Un ciclo pequeño y trazable

Explorar → proponer → revisar specs y tareas → implementar → verificar → archivar. La propuesta se corrige antes de producir código.

  • OpenSpec Quickstart
  • Instalación y configuración
  • Esquema spec-driven
  • Spec Kit: SDD walkthrough
Taller: pide una propuesta OpenSpec para una función pequeña; revisa propósito, requisitos, diseño y tareas. Corrígela hasta aprobarla, sin implementar aún.
Semana 6 · Métodos modernos

Elegir el método según el cambio

Compara OpenSpec, Spec Kit, briefs ligeros, BDD y TDD. No toda errata necesita un proceso largo.

  • GitHub Spec Kit
  • Filosofía SDD
  • Martin Fowler: TDD
Taller: describe la misma mejora con OpenSpec y un brief de una página; compara revisión, claridad y testabilidad.
Semana 7 · Agente de código

Construir por cambios pequeños

Modo plan, contexto, límites, diff, ejecución local y depuración con evidencia.

  • GitHub Copilot: empezar
  • OpenAI Codex: guía oficial
  • Cursor Docs (elige una herramienta)
Taller: implementa una tarea aprobada; pide que explique los archivos tocados. Revisa en móvil y ordenador; reporta cualquier fallo reproducible.
Semana 8 · Pruebas y revisión

Comprobar como usuario y revisor

Pruebas manuales, casos límite, regresión, accesibilidad y criterios de aceptación.

  • Playwright: introducción a pruebas web (automatización opcional)
  • W3C: evaluar accesibilidad
  • GitHub Skills: revisar PRs
Taller: escribe 10 pruebas en lenguaje cotidiano, pide evidencia de ejecución y comprueba manualmente cinco.
Semana 9 · GitHub Actions

Automatizar comprobaciones

Workflow, evento, job, steps, runner, secrets, permisos y logs. Entiende una Action antes de activarla.

  • GitHub Learn: Actions para principiantes
  • GitHub Docs: cómo funciona Actions
  • GitHub Skills: Hello Actions
Taller: configura validación HTML al abrir un PR. Lee los logs y corrige un fallo intencional.
Semana 10 · Publicar

Del repo al sitio vivo

GitHub Pages, build/deploy, dominio, HTTPS, comprobación y rollback.

  • GitHub Pages Quickstart
  • Pages con workflows
  • Vídeo oficial de Pages
Taller: publica el sitio de práctica, haz un cambio pequeño por PR, comprueba la URL y prueba cómo revertir.
Semana 11 · Seguridad y costes

Proteger repo, cuenta y datos

Secretos, mínimos permisos, dependencias, privacidad, prompt injection, licencias y límites de gasto.

  • GitHub: seguridad
  • Seguridad en GitHub Actions
  • OWASP Top 10 para apps LLM
Taller: revisa un repo de práctica en busca de secretos, permisos excesivos y dependencias desconocidas. Pide explicación antes de aplicar cambios.
Semana 12 · Proyecto integrador

Construir y presentar un producto

Idea → brief → specs → plan → tareas → PRs → pruebas → Actions → publicación → retrospectiva.

  • Repite el ciclo OpenSpec
  • Repasa GitHub PR
Entrega: demo online, repo con README, spec viva, historial, workflow, pruebas y límites conocidos. Pide a otra persona completar una tarea sin guiarla.

Comprobación final

Confirma la evidencia que puedes mostrar de tu proyecto.

Glosario rápido

Spec

Descripción verificable de lo que el producto debe hacer.

Commit

Instantánea de cambios guardada en el historial.

Pull request

Propuesta para revisar cambios antes de integrarlos.

Action

Automatización ejecutada por un evento.

SDD

Desarrollo guiado por especificaciones vivas.

Deploy

Publicar una versión accesible en un entorno.
